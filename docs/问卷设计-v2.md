# 问卷设计 v2 · 动机拆解版

> **v1 的问题**：把"地域"当成一个维度。可对学生来说，「离家近」和「想在大城市」是两种完全不同的偏好，权重不该加在一起，算法也该分开算。
>
> **v2 的做法**：问卷不问"你多看重地域"，而是问"你为什么要这个地域"；每个具体动机单独对应一条可计算规则。

---

## 一、拆维原则

```
一个维度如果内部包含互相冲突的动机，就不能当一维用。
```

| v1（粗） | v2（拆开） |
|---|---|
| 城市 / 离家近 | ① 离家近 ② 想去大城市 ③ 生活成本低 ④ 某个特定城市 ⑤ 和伴侣/同学一起 |
| 薪资回报 | ① 起薪高 ② 收入涨得快 ③ 有绩效/奖金 ④ 包吃住 |
| 稳定可控 | ① 有编制 ② 不裁员 ③ 行业稳定 ④ 公司够大不倒 |
| 专业对口 | ① 专业完全对口 ② 不排斥相关岗位 ③ 只要能进去就行 |
| 招聘规模 | ① 招的人多（机会大） ② 岗位选择多 |
| 行业方向 | ① 想进某个行业 ② 无所谓行业 |

**注意：拆开之后，有些动机在企业数据里根本采不到**（如"收入涨得快""有编制""和伴侣一起"）。
这些必须当场判定为「不可算」，转成现场要问的问题，**不能硬塞进排序制造未知**。

## 二、动机 → 可算信号对照表

**这是整份设计最核心的一张表。能算的进排序，不能算的进「现场问」。**

### A. 地域类

| 动机 | 企业端信号 | 能算 | 缺失时 |
|---|---|---|---|
| 离家近 | `city == home_city` | ✅ 高覆盖 | 学生没填家乡 → 不可算 |
| 想去大城市 | `city ∈ 一线/新一线表`（需静态城市表，约 20 城） | ✅ 高覆盖 | city 未知 → 中性 |
| 生活成本低 | `city ∈ 二三线表` | ✅ | 同上 |
| 想去某个特定城市 | `city ∈ region[]` | ✅ | 同上 |
| 和伴侣/同学一起 | 无此字段 | ❌ | **现场问** |

### B. 薪资类

| 动机 | 信号 | 能算 |
|---|---|---|
| 起薪高 | `salary` 里的月薪数字分档 | ✅ ~45% |
| 收入涨得快 | 无（要历年数据） | ❌ 现场问 |
| 有绩效/年终 | `salary` 里出现"绩效/13薪/年终" | ⚠️ 弱信号 |
| 包吃住 | `requirements` 里出现"包吃住/提供住宿" | ⚠️ 弱信号 |

### C. 稳定类

| 动机 | 信号 | 能算 |
|---|---|---|
| 有编制 | `nature == 事业单位` 或 `央企`（部分） | ⚠️ 近似 |
| 不裁员 | 无 | ❌ 现场问 |
| 行业稳定 | `industry ∈ {政府事业, 教育, 能源, 医药}` | ✅ 近似 |
| 公司够大 | **无规模字段** | ❌ 现场问 |

### D. 岗位类

| 动机 | 信号 | 能算 |
|---|---|---|
| 专业完全对口 | `title+requirements` 与专业/方向匹配 | ✅ ~50% |
| 不排斥相关岗位 | 同上，门槛放宽 | ✅ |
| 岗位选择多 | `jobs.length ≥ 5` | ✅ ~50% |
| 招的人多 | `headcount 合计` 分档 | ✅ ~40% |
| 能学到东西 | 无 | ❌ 现场问 |

### E. 行业类

| 动机 | 信号 | 能算 |
|---|---|---|
| 想进某个行业 | `industry ∈ 偏好行业` | ✅ ~85% |
| 无所谓行业 | 不给权重 | ✅ |

## 三、问卷正文

**共 12 题。核心变化：B 段不再让人"分 100 分给 6 个大类"，而是让人"从具体动机里选 3 个并排序"。**

### A. 你是谁（3 题）

**A1. 年级**：大四 / 研三 / 其他

**A2. 专业大类**：工科-制造 / 工科-IT / 经管 / 医药卫生 / 人文社科 / 法学教育 / 农林 / 其他

**A3. 最想找的岗位方向（最多 3 个）**
软件开发 / 数据分析 / 算法 / 硬件电子 / 机械结构 / 生产工艺 / 质量管理 / 财务 / 审计 / 金融业务 / 法务 / 人力资源 / 行政 / 供应链 / 采购 / 物流 / 市场 / 销售 / 运营 / 内容 / 研究 / 设计 / 临床医护 / 教学科研 / 其他

### B. 你最看重什么（2 题，核心）

**B1. 下面这些"具体的理由"，选 3 个对你最重要的，并按重要性排序**

> 每项都是"一个能单独讲清楚的理由"，不是大类别。

| 组 | 选项 |
|---|---|
| **地域** | ① 离家近 ② 想去大城市 ③ 生活成本别太高 ④ 就是想去某个城市 |
| **钱** | ⑤ 起薪就要高 ⑥ 以后涨得快 ⑦ 有绩效/年终奖 ⑧ 包吃住 |
| **稳定** | ⑨ 有编制 ⑩ 不容易裁员 ⑪ 行业本身稳定 ⑫ 公司够大不会倒 |
| **岗位** | ⑬ 专业完全对口 ⑭ 相关岗位也行 ⑮ 岗位选择多 ⑯ 这家招的人多 |
| **行业** | ⑰ 想进某个特定行业 ⑱ 行业无所谓 |
| **其他** | ⑲ 能学到东西 ⑳ 跟同学/伴侣在同一个城市 |

**怎么用：** 第 1 名得 50%，第 2 名 30%，第 3 名 20%。
→ 汇总 60–90 份，就知道**全校最看重的到底是"离家近"还是"大城市"**，这两个数字会分开出现，不会被"地域"这个大类吃掉。

**B2. 会考虑和专业不相关的工作吗？**
只看对口的 / 优先对口，相关的也看 / 不限专业

### C. 你的底线（2 题）

**C1. 倾向的企业性质（最多 2 个）**：央企 / 国企 / 民企 / 外企 / 合资 / 事业单位 / 不限

**C2. 期望城市（最多 3 个）+ 家乡城市**
南京 / 苏州 / 无锡 / 常州 / 上海 / 杭州 / 合肥 / 其他____
家乡：____（选填，**不填的话「离家近」这一项就没法算**）

### D. 现场行为（3 题，不参与打分）

**D1. 进场前做了什么准备？** 查过几家 / 扫了一眼名单 / 什么都没看

**D2. 停下来第一个理由**（单选）：
听说过这家 / 岗位对口 / 招牌写着招很多人 / 摊位人多跟着看 / 随便走

**D3. 什么情况直接走开**（多选）：
专业不对口 / 岗位不明确 / 只招有经验的 / 薪资没写 / 排队太长 / 没人

### E. 离场后（2 题）

**E1. 今天聊了几家？几家值得？**

**E2. 有没有哪家是你原本会走过去、后来发现其实不错的？**

### F. 开放题

**F1. 如果只能现场问企业一个问题，你问什么？**

## 四、从问卷到权重的算法

**不是取平均，是两步映射。**

### 第一步：动机出现频率 × 排名权重

```
每个动机的得分 = Σ（第1名×50 + 第2名×30 + 第3名×20）
然后归一化到 100
```

结果会长这样（示意）：

| 动机 | 得分 | 能不能算 |
|---|---|---|
| 离家近 | 18.4 | ✅ |
| 起薪就要高 | 16.2 | ✅ |
| 专业完全对口 | 15.0 | ✅ |
| 不容易裁员 | 12.1 | ❌ **采不到** |
| 想去大城市 | 10.3 | ✅ |
| 岗位选择多 | 8.9 | ✅ |
| 能学到东西 | 7.2 | ❌ **采不到** |
| 其他… | … | … |

### 第二步：不可算的按比例还给可算的

```
可算动机总分 = 18.4+16.2+15.0+10.3+8.9 = 68.8
归一化系数 = 100 / 68.8

离家近  → 26.7
起薪高  → 23.6
对口    → 21.8
大城市  → 15.0
岗位多  → 12.9
```

**这五个数就是新的默认权重，加起来正好 100。**

**同时报告里必须写清那句：**

> 问卷里 31.2% 的权重落在我们采不到的维度上（不裁员、能学到东西）。
> 这部分转型成「一页纸上的现场提问」，不计入排序。

**这句话是这份设计最值钱的地方**——它诚实，而且给了下一步方向。

## 五、三端重构

### 采集端 `fair.html`

| 动作 | 字段 |
|---|---|
| **改** | `values` 从 6 个大类 → **B1 的动机排序**（选 3 排序） |
| **改** | 新增 `motives: [{id: "离家近", rank: 1}, ...]` |
| **保留** | `region`、`home_city`、`major_fit`、`target_company_types` |
| **新增** | 期望月薪档位（5 档，用于「起薪高」） |
| **删除** | `target_stage`（写死校招）、`timeline` |

### 企业端（李欣）

| 动作 | 字段 |
|---|---|
| **必须补** | `jobs.length`、`headcount` 合计 → 支撑「岗位多」「招人多」 |
| **必须补** | `industry` 准确度（现 ~85%）→ 支撑「行业偏好」 |
| **新增静态表** | 城市分级表（一线/新一线/二三线，约 30 城）→ 支撑「大城市」「生活成本」 |
| **可删** | `urgency`（0%）、`group`（20%） |

### 匹配端（夏冉燃）

| 动作 | 说明 |
|---|---|
| **换维度** | 从「薪资/稳定/成长/自主/影响/平衡」→ **「离家近 / 大城市 / 起薪高 / 专业对口 / 岗位多 / 行业偏好」** |
| **地区拆算** | 同一个 `city` 字段，算出三个独立分数：是否家乡、是否大城市、是否期望城市 |
| **删死权** | 紧急程度 |
| **门槛化** | 学生选「只看对口」→ 方向变准入门 |
| **未知放行** | `nature`/`industry` 的「未知」合法化 |

## 六、为什么这样拆才对

拿「地域」举例：

| 学生 | 看重 | 同样一批企业，排序结果 |
|---|---|---|
| A | 离家近（盐城） | 盐城/南通的企业排前面，上海排后面 |
| B | 想去大城市 | 上海/杭州排前面，盐城排后面 |

**如果"地域"是一个维度，A 和 B 会得到同一份结果**——因为他们都"看重地域"。
**拆开之后，同样一句"我看重地域"，两个人排出来的顺序完全不同。**

这就是你说的那件事。
