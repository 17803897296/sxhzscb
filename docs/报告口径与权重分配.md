# 报告口径与权重分配规则

> 核心思路：**不排除任何一项。**
> 完整报告学生看重的排序，然后只在「会前能准备」的那部分动手；
> 权重按**全局排名位置**分配，不管我们最终能覆盖几项。

---

## 一、三段式结构

```
① 调查：学生找工作看重什么 → 完整排序（74 项，一项不删）
        ↓
② 分类：哪些能在会前准备，哪些只能现场问
        ↓
③ 权重：在「能准备」的子集里，按它们在 ① 里的排名分配 100 分
```

**关键：①②③ 是三件事，不能因为 ② 覆盖不全就回头改 ① 的排名。**

---

## 三、② 什么算「会前能准备」

只有两类能提前做，其余都留到现场：

| 能准备 | 准备成什么 |
|---|---|
| **位置** 展位号、楼层、区域 | 地图上标出来，告诉你哪几家挨着 |
| **身份** 企业名、性质、城市、行业 | 卡片上写清楚 |
| **岗位线索** 岗位名、职责、招聘人数 | 岗位表 |
| **匹配度** 和你专业/方向/城市的匹配 | 优先级排序 |
| **现场问题** 采不到的那些 | 印成一页纸，站在摊位前问 |

**不能准备但很重要的例子**：加班、裁员、晋升、氛围、领导。
这些**永远不在企业公开信息里**，只能现场问——所以我们把它们变成本子上的问题。

---

## 四、③ 权重分配：按排名，不按覆盖率

### 规则

```
只在我们能覆盖的子集里分配 100 分
每一项的权重 ∝ 1 / (它在前面的全局排名)
最后归一化到 100
```

**为什么用 1/排名**：第一名比第二名重要得多，不是等差关系；用倒数能体现"越靠前权重越大"且衰减快。

### 举例：假设我们只能覆盖第 3、6、8、15、28 名

| 全局排名 | 看重什么 | 1/排名 | 归一化后权重 |
|---|---|---|---|
| 3 | 离家近 | 0.3333 | **45.8** |
| 6 | 专业对口 | 0.1667 | **22.9** |
| 8 | 想去大城市 | 0.1250 | **17.2** |
| 15 | 招的人多 | 0.0667 | **9.2** |
| 28 | 行业稳定 | 0.0357 | **4.9** |
| | 合计 | 0.7274 | **100** |

**报告里就这么写：**

> 我们只能提前准备排在第 3、6、8、15、28 的项目。
> 按全局排名换算，它们分到 45.8 / 22.9 / 17.2 / 9.2 / 4.9 的权重。
> 排第 1、2、4、5 的项目我们没有数据来源，不计入排序，转为现场提问。

### 这个算法的好处

| 好处 | 说明 |
|---|---|
| 不撒谎 | 没覆盖的说没覆盖，不假装算过 |
| 不浪费 | 哪怕是第 28 名，也给了 4.9 分，不是 0 |
| 可扩展 | 以后企业端能多采一项，把它的排名代进去重算一遍就完事，不用改算法 |
| 可解释 | 老师问"凭什么这么分"，直接给他看 1/排名 这张表 |

## 五、写进报告的三句话

**1. 关于调查**

> 我们调查了 87 名同学的求职偏好，得到了完整的 74 项排序。

**2. 关于能力边界**

> 其中 14 项能从企业公开信息中获取，26 项只能做弱信号（写了才加分），34 项公开页面不会写。
> 后两类我们不做假数据，而是转成现场提问清单。

**3. 关于权重**

> 排序前十的项目里，我们能提前准备第 3、6、8 名；
> 按排名换算出它们的权重分别是 45.8、22.9、17.2。
> 这个权重不是我们拍的，是问卷排名算出来的。

---

## 六、对三端的要求（很小）

| 端 | 要改什么 |
|---|---|
| 采集端 | 问卷里保留完整 74 项排序（或它的简化版：选最重要的 10 项排序） |
| 企业端 | **不改字段**。它采什么我们就用什么 |
| 匹配端 | 权重不是写死的六维，而是**一份"可覆盖项 → 权重"的表**，由 ③ 算出来 |

**关键变化：匹配端的权重从"代码里写死"变成"配置文件"。**

```json
{
  "covered": [
    {"key": "home_distance", "rank": 3, "weight": 45.8},
    {"key": "major_fit",     "rank": 6, "weight": 22.9},
    {"key": "big_city",      "rank": 8, "weight": 17.2},
    {"key": "hiring_scale",  "rank": 15, "weight": 9.2},
    {"key": "industry_stable","rank": 28, "weight": 4.9}
  ]
}
```

**以后企业端多采一项，改这个 JSON 就行，不动代码。**

---

## 七、一句话

> **报告全部排名，只准备能准备的，权重按排名分配。**
> 覆盖不全不是缺陷，是这一版的边界——写清楚就行。
