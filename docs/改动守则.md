# 改动守则

护栏在 `ent_tools/gate.py`。**每次改完至少跑一次**：

```bash
cd ent_tools && python -X utf8 gate.py
```

它的逻辑是「棘轮」：不要求你把历史包袱一次清完，**只禁止任何一项比上次更差**。
指标变好会**自动**前进，只有变差才拦你。

### 它刻意不拦的东西

写新功能、加模块、写注释、拆函数、加测试 —— 这些都会让代码量涨，但都是对的事。
所以「文件数」「总行数」只在报告末尾作参考，不参与拦截。

第一版把它们当硬指标，结果我把 1 行硬编码路径改成 5 行（含三行注释说明为什么），
总行数涨 25，**修好一项反而被拦下**。护栏如果为「正确的事」收手续费，
人就会开始绕过它 —— 那比没有护栏更坏。

真该盯的是「单文件 / 单函数暴涨」，那说明所有新代码都塞进一个地方了。这两项 0 容差。

下面 8 条不是抽象原则，每一条对应这个项目**真实踩过的坑**。

---

## 1. 生成物不要手改

`demo/fair.html` 是 `build_fair_page.py` 的输出，不是源码。
要改它，改 `ent_tools/js/*.js`、`fair_report_js.py`、`job_recommend.py` 或
`intent_semantics.py`，然后重新构建。

> **为什么**：这个页面一度是「半手写 + 半被 patch 函数打补丁」的混合态，
> 改一处 JS 得先判断「改源文件还是改 patch」。现在构建时写
> `data/.page_stamp.json` 记 md5，手改会被 gate 的「生成物被手改」直接抓出来。

## 2. 同一份实现只留一份

发现第二个模块里有同名函数且结构一样，**抽到共用模块**，不要复制。

> **为什么**：`_call_raw` 曾有 5 份逐字相同的拷贝，改重试策略要改五处；
> 漏一处不会报错，只会「某个模块的缓存悄悄不生效」。这类问题已经发作两次了。
>
> 现状：`_load_cache` / `_save_cache` 各 5 份还在，gate 记着 **11 份多余拷贝**。
> 想还债就还（还一份指标降一份，自动前进），但**不许再多拷一份** ——
> 这个指标数的是「多余份数」不是「有几组重复」，所以拷第 3 份也会涨。
> 一开始我数的就是组数，验证时发现拷第 3 份指标不动，而蔓延正是屎山的形成方式。

## 3. 跨模块的字段名，全链路统一

一个字段从一个模块传到另一个模块之前，先 `grep` 它出现过几种写法。

> **为什么**：主营字段曾经一半写 `bizScope`、一半写 `biz_scope`，
> 两边各读各的、**都不报错**，表现是「明明填了主营，报告里是空的」。

## 4. 吞异常必须留痕

`except Exception: pass` 只允许出现在「单条失败不能拖垮整批」的位置，
且同一行或上一行必须有 log / print / 计数。

> **为什么**：踩过两次 —— 「日志说主营=有，库里是空」、
> 「`--scope-only` 分支提前 return 跳过落库」。都是静默降级，
> 跑完看起来全绿，数据是缺的。
> gate 只认 `except Exception`；捕具体类型（`except UnicodeDecodeError`）不算。

## 5. 改动要有「等价性验收」，不是「看着差不多」

替换/抽取/重排这类**不该改变行为**的改动，验收必须能一句话说清
「什么和什么完全相等」：

| 改动 | 验收方式 |
|---|---|
| 抽 JS 出 Python 文件 | 同一 payload 下新旧构建器输出 **md5 相同** |
| 无头渲染换 CDP | 8 个真实招聘页正文 **逐字等长** |
| 合并 LLM 调用 | 请求体 **逐字节比对**（这个测试当场抓到 `0` vs `0.0`） |

拿不出这种验收，就说明你还没想清楚「改坏了会怎样」。

## 6. 新模块不要用 `_` 开头

`_` 开头是「一次性脚本」的约定，`sync_repo._blocked()` 会把它排除出同步清单。

> **为什么**：CDP 复用层一开始叫 `_cdp.py`，本地跑得好好的，
> 但 clone 出来的实例 `import portal` 直接失败 —— 因为 `_cdp.py` 根本没进仓库。

## 7. 改了数据就重建页面，别分两步

用 `python -X utf8 refresh_all.py`，它串了 9 步：缓存体检 → 补字段 →
建 payload → 建页面 → 夹具 → 单测 → 护栏。

> **为什么**：出过「库里有新企业、报告还是旧的」，
> 因为采集和收尾原来是两个入口，中间漏一步没人发现。
> gate 的「页面比数据旧」就是盯这个。

## 8. 两套入口只留一套

新增流程之前，先确认没有第二套在做同一件事。

> **为什么**：`collect.py → companies.json`（118 家）和
> `collect_roster.py → 145 家` 并存过。危险不是混乱，是**有一天你会跑错那个**，
> 插进去 96 家不相干企业。

## 什么时候可以放宽基线

变好不用管，自动前进。变差只有两种情况该放：

1. **确实判断错了** —— 某条检查在这个项目不适用。那就**删掉这条检查**，
   并在 `gate.py` 里写明为什么删。**不要加 `--no-verify`，也不要注释掉**：
   留着一个需要绕过的规则，比没有规则更坏。
2. **临时确实要放宽** —— 用 `--force`，并在提交信息里写清理由。
   它的本意是「这次我认了，下次还回来」，不是日常操作。

## 这套东西自己的教训

设计过程中改了三轮，每一轮都是「拦错了人」或「拦不住」：

| 版本 | 问题 |
|---|---|
| 结构指纹阈值 0.75 | 28 组「重复」里 18 组是同名不同事，纯噪声 |
| 加「函数≥8行」+ 0.88 | 还是误报 `_key`（都是 json 后取 md5）、`judge` |
| 总行数当硬指标 | 修好一处硬编码反而被拦（改 1 行成 5 行） |
| 数「重复组数」 | 拷第 3 份指标不动，抓不住蔓延 |

现在用的：`ast.unparse` 还原源码逐字比 + 阈值 0.95（真拷贝 ≥0.954、非拷贝 ≤0.877，
0.88~0.95 之间一组都没有，是天然分界），数「多余份数」，规模指标退到参考区。

**每次改这个文件，都要拿真实代码验一遍「会不会误报」和「能不能拦住」。**
它自己坏了不会报错，只会慢慢变成没人看的摆设。

## 提交前自检

```bash
cd ent_tools
python -X utf8 gate.py                  # 只许持平或变好
python -X utf8 -m unittest discover -s tests
```

两项都过再提交。改了涉及页面的东西，再加一次 `refresh_all.py`。
