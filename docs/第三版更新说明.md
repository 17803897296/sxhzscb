# 第三版更新了什么

第一，代码整体做了重构，把五处屎山风险点都改了：LLM 调用合并成一份、前端 JS 从 Python 里抽出来、无头渲染改成复用一个浏览器、抓取工具去重、736 行的 build 拆成 443 行加 11 个小函数。

第二，采集端的岗位推荐修正了，之前经常残留计算机和管理类岗位，现在按「专业和经历匹配 → 专业匹配 → 不完全匹配但有门槛 → 专业能去但别人也能去 → 几乎无关」五层逐层放宽，推的都是专业相关能去的。

第三，匹配段的大模型推断换了路线，以前把学生意向塞给模型问「接不接得住」会编出搜不到的岗位名，现在先只看企业主营建岗位画像、比对交给本地代码做。

第四，命中/推断算法做了一串修正：按职能类判定取代凭专业课程推断、复核从二分类改成三态弃权、补行业简称同义词表、幻觉岗位名脱敏、校招公告没有就是没有、现场核实回流改结论。

第五，数据库扩到 14 张表，画像、现场反馈、测试记录都落库，提交画像即生效并后台重算，活库不入库、仓库只放只读种子。

第六，采集流程收口成一条命令，无头渲染从每次开浏览器改成多标签复用（8 页 47→21 秒），外部档案按逐字同名并入，写库只有一处且是合并不是覆盖。

第七，界面改成四端工作台（采集端 / 企业端 / 匹配端 / 测试端），按进度点亮徽标，尽可能美观。

第八，验收：虚拟自动化画像跑完整链路 45 秒，49 家企业 / 357 岗，跨专业残留为 0，四端 HTTP 200、58 个单测 OK，测完数据逐字节还原。

第九，按三套虚拟画像追踪判断路径后，又修了五处常识问题：方向不交叉的企业顺延到队尾不再占前排、工商信息页不再当真实招聘公告、家具厂的结构工程师不再被建筑学生当同名命中、复核弃权的相邻岗位改成现场问一句、职级和文案描述对齐。

第十，再扩到九套画像（计算机/财会/材料/文科/机械/空意向）深测后补了三处：没填意向的不再拿默认意向判「明确命中」、职级高的岗位不再误称「不同职能」、意向里混进空值不再把重算打崩导致页面 500。

第十一，校招来源核实重建岗位库：按岗位真实来源域名重判 145 家，82 家误标 web/未知的其实是校招、纠正为 90 家校招来源；同一企业多渠道岗位合并、只留带 URL 的真岗，删掉 279 条大模型推断补全的假岗。

第十二（2026-11-16～17 迭代，见《第三版技术细节》补记），六件事：

1. **企业端改成岗位上传框，数据库依然隐藏**——原来那页把库内 145 家企业全量渲染（200KB 内嵌数据），现在换成对话框式上传页：粘贴岗位信息/链接或传附件，提交进隐藏台账（`/api/jobs-upload`，页面不回显任何库内清单）；门户门禁文案同步，空提交服务端拒收。
2. **岗位推荐改成联网推荐**——之前模型靠「通用认知」想岗位名，会造词（招聘网站搜不到的职能描述）也会混进与专业关系不大的岗。现在先调 DeepSeek 独立 Search API 搜真实校招公告（标题+摘要+来源，证据缓存 6 小时），模型只准从证据里提岗位名，代码再落地校验：输出岗位名在证据原文里找不到的一律丢掉，「计算机类岗位」这类公告类别标签也拦；页面上联网模式会标「（联网搜索 · 真实校招口径）」。搜索失败自动降级纯模型口径，再降级规则兜底。
3. **推荐池与岗位库彻底解耦**——采集端推荐不再读 careersafari.db（库内岗位含大模型推断岗，会带偏学生自主选择、给匹配端喂答案形成循环污染），候选只依据专业+经历。
4. **画像×主营复检层**——命中判定不再只看「岗位名 ↔ 意向岗位」的字面：全通用意向（管培生/储备干部）× 字面同名岗位要过「企业主营是否容纳专业方向」这道闸（金融公司的管培生不再匹配物流专业选的管培生）；推断命中必须主营出现方向强词，主营为空不推断；被拦的转现场待问。前端换画像重算路径镜像同一规则。
5. **命中治理三连**——泛意向（研发工程师）×带方向岗位（软件工程师）不再硬命中转现场问；轮岗泛岗（管培生/培训生/储备干部）即使业务对口也只现场问；推断命中带箭头标记进报告，橙色标「推断命中，待现场核实」。
6. **未知字段保护与榜单恢复**——重采不再把旧库已知值冲成「未知」（六字段保护闸+旧库回填 26 家）；丢失的排名档案从交接包恢复（52 家有档位），门户补回「测试记录」入口。

注：通用岗位的方向推断已入库（69 条，按企业主营本地推、不用大模型），主营业务补全 144/145 家；排名档案那份文件缺失，所以当前报告里排名档位是 0。

还有一个已知问题留待下版改进：本科学生投博士岗会被判「明确命中」，学历门槛目前没参与判定，这次没动。

详细技术说明见《第三版技术细节》；踩过的坑与改动纪律见《改动守则》。

第十三（2026-11-17 demo 试用反馈，两件事）：

1. **推荐岗放宽到职能方向级 + 跨专业再拦一道**——试用反馈推荐岗太细（「京东新锐之星」这类企业项目名学生对不上），且仍有非本专业岗位混入。联网提示词改为「岗位名给职能方向级的通用叫法」：企业专名 / 项目名 / 地域 / 年份一律归一掉（「京东2026新锐之星（物流方向）」→「物流管培生」）；代码新增三道拦截：项目名黑名单（新锐之星 / 青苗 / 菁英 / 训练营…）、跨专业拦截（岗位名必须命中 biz_recheck 的专业方向词，tier3 另放行通用职能词，tier4 不拦）、「名字带领域词但干的明显是别的活」黑名单（电商美工这类——物流域有「电商」，但美工是设计岗）。实测物流 tier1 从公司专属岗名变成 物流管培生 / 仓储运营岗 / 供应链管理岗，化工 tier1 拦掉 6 个跑题岗。缓存键升到 rec-v11。
2. **三页面从「名义上」变「实际上」**——之前名单导入、匹配排行都挤在 fair.html 一个页面里（匹配端只是 ?report=1 的视图参数）。现在：学生端 fair.html 只管画像，聊完给「去匹配端」跳转卡片（离线双击模式保留原内联流程）；企业端 enterprises.html = 导入参会企业名单（match.js rosterOnly 模式，`/js/match.js` 服务端替换占位符后注入）+ 岗位上传框；匹配端是真正独立的 `demo/match.html`——同一套内联 JS，`window.__FORCE_REPORT` 启动即进报告视图，portal 的匹配端标签直接指向它。
