# 第三版更新了什么

第一，代码整体做了重构，把五处屎山风险点都改了：LLM 调用合并成一份、前端 JS 从 Python 里抽出来、无头渲染改成复用一个浏览器、抓取工具去重、736 行的 build 拆成 443 行加 11 个小函数。

第二，采集端的岗位推荐修正了，之前经常残留计算机和管理类岗位，现在按「专业和经历匹配 → 专业匹配 → 不完全匹配但有门槛 → 专业能去但别人也能去 → 几乎无关」五层逐层放宽，推的都是专业相关能去的。

第三，匹配段的大模型推断换了路线，以前把学生意向塞给模型问「接不接得住」会编出搜不到的岗位名，现在先只看企业主营建岗位画像、比对交给本地代码做。

第四，命中/推断算法做了一串修正：按职能类判定取代凭专业课程推断、复核从二分类改成三态弃权、补行业简称同义词表、幻觉岗位名脱敏、校招公告没有就是没有、现场核实回流改结论。

第五，数据库扩到 14 张表，画像、现场反馈、测试记录都落库，提交画像即生效并后台重算，活库不入库、仓库只放只读种子。

第六，采集流程收口成一条命令，无头渲染从每次开浏览器改成多标签复用（8 页 47→21 秒），外部档案按逐字同名并入，写库只有一处且是合并不是覆盖。

第七，界面改成四端工作台（采集端 / 企业端 / 匹配端 / 测试端），按进度点亮徽标，尽可能美观。

第八，验收：虚拟自动化画像跑完整链路 45 秒，49 家企业 / 357 岗，跨专业残留为 0，四端 HTTP 200、58 个单测 OK，测完数据逐字节还原。

第九，按三套虚拟画像追踪判断路径后，又修了五处常识问题：方向不交叉的企业顺延到队尾不再占前排、工商信息页不再当真实招聘公告、家具厂的结构工程师不再被建筑学生当同名命中、复核弃权的相邻岗位改成现场问一句、职级和文案描述对齐。

第十，再扩到九套画像（计算机/财会/材料/文科/机械/空意向）深测后补了三处：没填意向的不再拿默认意向判「明确命中」、职级高的岗位不再误称「不同职能」、意向里混进空值不再把重算打崩导致页面 500。

第十一，校招来源核实重建岗位库：按岗位真实来源域名重判 145 家，82 家误标 web/未知的其实是校招、纠正为 90 家校招来源；同一企业多渠道岗位合并、只留带 URL 的真岗，删掉 279 条大模型推断补全的假岗。

注：通用岗位的方向推断已入库（69 条，按企业主营本地推、不用大模型），主营业务补全 144/145 家；排名档案那份文件缺失，所以当前报告里排名档位是 0。

还有一个已知问题留待下版改进：本科学生投博士岗会被判「明确命中」，学历门槛目前没参与判定，这次没动。
