# 第三版更新说明

> 一句话：这一版把「能跑」变成「跑得稳、改得动」——代码拆了五处、岗位推荐按贴合度分了五层、界面改成四端工作台。
> 所有数字都来自 2026-11-16 的实测，不是估计。

## 一、代码整体重构：五处屎山风险，逐处拆掉

| # | 原来 | 现在 | 怎么证明没改坏 |
|---|---|---|---|
| 1 | 大模型调用 5 份逐字拷贝，改重试策略要改 5 处 | 合并为 `ent_tools/llm.py`（84 行），三个调用方共用 | 请求体**逐字节比对**；缓存时间戳不变，零模型调用 |
| 2 | 三段前端源码埋在 `build_fair_page.py` 里，1,911 行 Python 里夹着 JS | 抽到 `ent_tools/js/`：`shim.js` 208 / `recommend.js` 375 / `match.js` 849 行，构建器降到 488 行 | 同一 payload 下新旧构建器输出 md5 相同（976,239 字节） |
| 3 | 每次抓取都冷启动一个无头 Edge，单页 5~18 秒 | `ent_tools/cdp.py`：常驻浏览器 + 每页一个标签页，失败自动退回 `--dump-dom` | 冷启动 165 ms；8 个真实招聘页 47.4 → 21.3 秒，7 页正文逐字等长 |
| 4 | `strip_html` / `fetch` / `UA` 在 collect、enrich、portal 各一份 | 收进 `ent_tools/webtext.py`；多余拷贝 11 → 7 份 | 真实页面（40 万字）与边界用例上三份旧实现逐字一致 |
| 5 | `fair_bridge.build` 736 行，内部一个 `for` 占 418 行 | 拆出 11 个具名零件，`build` 降到 443 行，最长 `for` 降到 239 行 | 固定 `PYTHONHASHSEED=0`，分五步拆、每步比对 payload，五次都是**抹掉时间戳后逐字相同** |

配套改动：首次提交并整理历史；一次性脚本搬进 `scratch/`（根目录 69 → 60 个 py）；`merge_handoff_jobs.py` 去掉写死的本机桌面路径，改环境变量。

关于护栏：曾做过一版「棘轮门禁」（13 项指标，只禁变差），试运行后删掉了，理由记在 `docs/改动守则.md` 第 9 节——**会拦人的指标最终都会被绕过，而被绕过的护栏比没有更坏**；它还会让人把新代码塞进旧地方以免指标变差，那正是屎山的成因。现在只留一个不拦人、不在流水线里的 `health.py`，只打印数字。

## 二、采集端岗位推荐：按五个贴合度层级逐层放宽

不是「推得多」，而是**每一层都有明确的用人边界**。以自动化专业为例：

| 层级 | 口径 | 实测推荐（自动化） |
|---|---|---|
| 1 | 专业和经历匹配 | 电气工程师、电控工程师、自动化工程师、嵌入式硬件工程师 |
| 2 | 专业匹配（忽略经历细节） | 电气设计工程师、PLC 工程师、电控软件/硬件工程师、自动化系统工程师 |
| 3 | 专业不完全匹配但能去、有专业门槛 | 电气运维、仪表、供配电、电气调试、维修工程师、运行操纵员 |
| 4 | 专业能去，但很多专业也都能去 | 质量专员、生产计划专员、采购专员、技术销售专员、生产管理管培生 |
| 5 | 和专业几乎无关（教培不限专业的老师等） | 学科教师、课程顾问、教务专员、招生专员——**只有学生明确接受不限专业岗位才开放** |

具体到实现上的修正：

- **挡住跨专业残留**：非计算机/信息大类不再推「软件开发 / 前端 / 后端 / 算法 / 数据开发」，非经管类不再推「管培生 / 储备干部 / 业务运营」，除非实习、竞赛、论文里确实有对应项目支撑。
- **相邻层按学科大类分表**：不再把隔壁专业整张表照抄过来；机械设计、结构、仿真这类筛隔壁背景的岗不推给自动化。
- **岗位按用人要求分三档**：切合专业 / 相邻有门槛 / 通用职能，避免一个大类表把「研发工程师」当成万能入口。
- **换层不重复**：低一层的岗位名会作为已展示项喂给模型，逐层放宽时不会把刚划走的岗再推一遍。
- **规则池兜底**：模型不可用时仍按分层规则给出岗位，不会直接空白。

## 四、界面：改成四端工作台

入口仍是 `/`，但不再是一个页面塞下全部内容，而是四个各管一段的页面，由统一门户切换、按进度点亮徽标：

| 端 | 页面 | 做什么 |
|---|---|---|
| 采集端 | `/fair.html` | 简历 + 四个问题 + 偏好权重，生成画像 |
| 企业端 | `/enterprises.html` | 145 家全量名录，**不做匹配筛选**，先看池子里有什么 |
| 匹配端 | `/fair.html?report=1` | 排行、对口依据、现场问什么 |
| 测试端 | `/test_users.html` | 三套内置虚拟画像，一键验收「换一个学生会怎样」 |

测试记录后台 `/tests.html` 独立于这四端，只用来查看/清理测试脏数据。页面统一由构建器生成，不在 `demo/` 里直接手改。

## 五、这一版的验收：拿一个虚拟画像跑完整链路

虚拟画像 D：**自动化 / 本科 / 南京工业大学 / 2027 届 / 国企优先**，意向岗位为电气工程师、自动化工程师、PLC 工程师、设备工程师，技能 PLC、电气原理图、电机拖动、单片机。

结果（提交画像 → 后台重算 → 拉回报告）：

- 45 秒完成重算；参与排序 **49 家企业 / 357 条岗位**，明确命中 17、待核实 32。
- Top 1 是运达能源科技集团（电气工程师，明确命中）；Top 9 是中电科 55 所（设备维护工程师，同一大类）。
- 扫描全部命中岗位里的计算机/软件/前端/算法/管培生/销售/教师等关键词：**没有跨专业残留**。唯一含「管培生」的是「设备维修管培生」——设备维修方向，对自动化是相关岗，不是管理类误推。
- 五层推荐逐层请求，层级文案与内容对得上；第 5 层「学科教师」等只在接受不限专业时才出现。
- 四端页面均 HTTP 200；58 个单测 OK；规则回归退化 0 项。
- 测试完成后数据库、payload、页面**已还原到测试前状态**（生效画像仍是原来的自动化画像）。

## 六、诚实说明：还没做的

- `fair_bridge.build` 仍有 443 行；多余拷贝仍有 7 份（每一份都会改行为或改缓存键，不适合批量删）；51 处静默吞异常没批量加日志——一动就会作废该模块全部 LLM 缓存。
- 既有问题未修：`hash(name)` 排序不可复现、`sync_repo.py` 绑本机、服务不读 `$PORT`、没有 Dockerfile / CI。
- 不会再做一个会拦人的门禁；写代码时的自由度优先于「看起来有保护」。
