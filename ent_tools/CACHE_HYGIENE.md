# 缓存卫生规则（改完代码怎么会"干净"）

## 一句话
改完任何判定逻辑，跑一条：`python refresh_all.py`。不要靠记忆删缓存。

## 为什么会有这套东西
过去每次改动都栽在同一处：**代码改了，缓存 key 没变，旧结论继续被当新结论用**。
具体踩过的坑：

| 坑 | 现象 | 根因 |
|---|---|---|
| 换模型 | 页面标 `mode=llm`，实际是上一个模型的结果 | 池子 key 里没有模型名 |
| 改规则 | 归因还是「同属相关类岗位」这种旧文案 | 语义缓存 key 里没有代码指纹 |
| 改词表 | 推荐岗位名还是上一版前缀 | 同上 |
| 换画像 | 报告里的「大模型判断依据」是别人的 | 缓存回退时从任意旧画像里捡 |

## 现在的做法
`cache_guard.py` 把**依赖模块的语法树指纹**塞进每个缓存的 key：

```
key = md5(缓存名 | 依赖模块 AST 指纹 | 业务参数...)
```

- 改注释、空行、格式 → 指纹不变，缓存继续用（不会白重建）。
- 改任何一行逻辑或提示词 → 指纹变 → 旧缓存判定失效，自动归档到
  `data/_stale_cache/`（保留最近 6 份，可回溯），用到时重建。
- 失效的缓存**不会被沿用**。模型调用失败时也只能沿用"同一版本代码"的结果，
  宁可退化成字面匹配，也不把旧 bug 装回去。

## 两条命令
```bash
python cache_guard.py status      # 体检：哪个缓存是本版代码生成的
python refresh_all.py             # 标准收尾：体检 → 重建 payload → 重建页面 → JS 校验 → 三套测试
python cache_guard.py purge       # 强制全部重建（换模型/改架构时用）
```

`refresh_all.py` 任何一步失败即停、退出码非 0。

## 页面上的可见性
`fair_payload.json` 顶层带 `cache_status`，报告页「更多设置」里显示一行
「缓存体检：N 项，本版代码生成 M 项」。有异常会直接写出来，
比如现在唯一一条：

> `llm_match`：表 241 行，早于本机制、无生成指纹：岗位名/理由不采信，已按当前语义层重算

这条不是故障，是诚实标注——那张表是 11-10 用旧画像生成的，现在只拿它的
`state` 当弱信号，岗位名和理由一律按当前语义层重算。

## 新增缓存时必须做的
1. 在 `cache_guard.REGISTRY` 登记：名字、路径、**依赖哪几个模块**、类型
   （`derived` / `snapshot` / `db` / `artifact`）。
2. key 用 `cache_guard.key(name, *业务参数)`，别自己拼 md5。
3. 写文件时带上 `"_cg": cache_guard.stamp(name, model=...)`。
4. 读文件的回退分支只允许沿用「同指纹」的旧结果。

漏了第 1 步，`status` 会把它当"旧格式"报出来——这就是下一轮脏数据的源头。
