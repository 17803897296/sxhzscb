# 岗位数据库接入说明

目标：**用户搜索企业时，先查数据库；数据库没有再走在线搜索。**

现在只建链条，不决定数据库 schema，也不写入数据库内容。

## 查询顺序

```text
用户搜索企业
   ↓
JobStore.lookup(company)
   ├─ 命中 → 直接返回（data_source = "db"）
   └─ 未命中
        ↓
   portal.build(company) 在线搜索
        ↓
   JobStore.save(company, item) 写回（可选）
        ↓
   返回（data_source = "online"）
```

## 接入点

文件：`ent_tools/job_store.py`

```python
class JobStore:
    def lookup(self, company: str):
        """命中返回企业记录 dict；未命中返回 None。"""
        return None

    def save(self, company: str, item: dict):
        """把在线结果写回数据库；可以不实现。"""
        return None
```

组员实现自己的子类，然后替换：

```python
import job_store

class MyJobStore(job_store.JobStore):
    def lookup(self, company):
        # TODO: 查 SQLite / Postgres / 现有服务
        ...

    def save(self, company, item):
        # TODO: upsert
        ...

job_store.set_store(MyJobStore())
```

> 注意：`portal.py` 的 `/api/lookup` 会用 4 个线程并发调用 `lookup/save`，实现需要线程安全（或自己加锁）。

也可以根据环境变量在 `get_store()` 里选择实现，目前默认是 `NullJobStore`（永远未命中，全部走在线）。

## 已经被接到哪些地方

1. `ent_tools/portal.py` 的 `/api/lookup`
   - 先 `job_store.lookup`
   - 未命中再走 `CACHE` / 企业端离线库 / 在线搜索
   - 在线搜索完成后 `job_store.save`

2. `ent_tools/company_jobs_mcp.py`
   - MCP 工具 `search_company_jobs`
   - 内部调用 `job_lookup.lookup_company`
   - 返回里带：
     ```json
     { "data_source": "db" | "online", "db_hit": true | false }
     ```

## 链条测试

```text
ent_tools/tests/test_job_lookup_chain.py
```

覆盖：

- 第一次未命中 → 在线搜索 → 写库
- 第二次命中 → 直接返回，不再在线搜索
- NullJobStore → 永远走在线

运行：

```powershell
cd ent_tools

```
