# 批量查企业资料的提示词

给一批企业名，让模型输出 `raw_research.json` 的条目。**一次别超过 10 家**，多了它会开始编。

---

## 提示词

```text
你在帮我整理双选会参会企业的公开资料。

【输出格式】
只输出一个 JSON 数组，不要任何解释文字。每家企业一条：

[
  {
    "name": "企业全称（和输入完全一致，不要改写）",
    "nature": "央企|国企|民企|外企|合资|事业单位 之一",
    "city": "总部所在城市",
    "industry": "制造|医药|IT|金融|建筑|能源|消费|物流|教育|政府事业|其他 之一",
    "jobSource": "校招公告|社招信息|主营业务推测|未知 之一",
    "source": "公开材料的链接或可定位标识；没有就写 未知",
    "date": "资料核对日期 YYYY-MM-DD",
    "text": "公开材料的原文，整段照抄",
    "jobs": [
      {
        "title": "岗位名称",
        "requirements": "学历与专业要求，按原文",
        "headcount": 数字或 "未知",
        "urgency": "高|中|低|未知",
        "group": "岗位所属部门；原文没有就写 未知",
        "salary": "薪资，原文照抄；没有就写 未知"
      }
    ]
  }
]

【四条铁律】

1. text 必须是**原文照抄**，不许概括、不许改写、不许自己组织语言。
   下游要把 jobs 里的岗位和它逐字比对，改一个字就废。
2. 查不到就写 "未知"。不许编岗位、不许编人数、不许编薪资。
   宁可一条岗位都没有，也不要写一个看着像的。
3. jobSource 怎么选：
   - 找到校招公告 → "校招公告"
   - 只找到社招/招聘平台 → "社招信息"
   - 只找到主营业务介绍，岗位是从业务推的 → "主营业务推测"，且 text 必须是那段业务原文
   - 什么都没找到 → "未知"，jobs 写 []
4. uncertainty 不要写在字段里。字段只能是上面那些枚举值，不许写"可能是""大概"。

【顺序】
先搜"企业名 + 校园招聘 / 2026届"，找到就照抄。
找不到再搜"企业名 + 社会招聘"。
再找不到就搜"企业名 + 主营业务"，用这段原文去推。
都找不到，整条填"未知"。

现在开始，这批企业是：
（在这里贴企业名，一行一个）
```

---

## 拿到结果后

1. 粘进 `data/raw_research.json`（多批就拼成一个数组）
2. 跑 `python -X utf8 build_cache.py`
3. 打开 `data/build_report.md`

**报告里出现「降级」的企业，就是模型没给出可验证原文的那批，需要人工补。**

---

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 大量「降级为未知」 | 模型给的 text 是概括的，不是原文 | 让它重查这家，要求贴原文 |
| `jobEvidence` 对不上 | text 被改写过 | 同上 |
| 岗位一堆但 `jobSource` 是「校招公告」却查无此公告 | 模型编的 | 抽查 5 家上官网核对 |
| `industry` 归一到「其他」 | 说的是细分行业（如"精密制造"） | 在 `build_cache.py` 的 `INDUSTRY_MAP` 里加一条 |

---

## 抽样验收

**每批抽 3 家，上官网核对 `nature` 和 `city`。**

3 家里错 1 家以上，这批全部重跑——不是数据问题，是提示词没约束住。
