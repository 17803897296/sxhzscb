## 5. 每个条件分别筛掉几家

实际页面执行的：

1. **LLM 初筛**：118 → 43，筛掉 **75 家**。
2. **岗位为空**：43 → 10，筛掉 **33 家**。

如果再按更严格的数据条件继续卡：

3. **岗位来源必须是校招公告**：10 → 7，筛掉 **3 家**（只有主营业务推测）。
4. **城市必须可用**：7 → 6，筛掉 **1 家**（浙商证券，城市未知）。
5. **企业性质必须已知**：6 → 6，筛掉 **0 家**。
6. **行业必须明确（不能是“其他”）**：6 → 5，筛掉 **1 家**（联检，行业其他）。

所以：

- 只要求“有岗位”：**10 家**。
- 要求“有真实校招公告”：**7 家**。
- 要求“真实校招 + 城市/性质/行业都能用”：**5 家**。

## 6. 代码原因与修复

旧逻辑在 `ent_tools/build_fair_page.py` 的快速搜索和全量搜索里都是：

```js
const got = d.companies || [];   // 有岗位
const missed = d.missed || [];  // 没岗位
// 旧逻辑只把 got 合并进 POOL，missed 不参与
const byName = new Map(got.map(c => [c.name, c]));
POOL = POOL.map(c => byName.get(c.name) || c).concat(got.filter(...));
```

`missed` 只进了搜索报告，没有进 `POOL`，所以没岗位的企业从匹配结果里消失。

已改为：

```js
const incoming = [...got, ...missed];  // 有岗位 + 没岗位都进池
// 同名时优先保留有岗位的版本
```

修复后实测：把这次 43 家全部送入全量搜索，页面显示 **43 行**。原始缓存是 **10 家有岗位 / 33 家“岗位未查到”**，有岗位的 10 家按分数分三档（3 / 4 / 3），没岗位的 33 家单独放在「资料不全」。

重跑这 33 家后，规则抽取补到 3 家（国元证券、北京海量数据、江苏共创）；再用无头浏览器补到腾讯、京东方。现在是 **15 家有岗位 / 28 家资料不全**，三档变为（5 / 6 / 4）。状态栏明确写：

```text
名单 43 家 · 补到岗位 10 家 · 没抓到 33 家（仍保留，按企业资料参与匹配）
```

## 7. 建议

1. 没岗位的企业不要丢，保留在结果里，并标“岗位未查到”。
2. 给“仅企业资料、无岗位”的企业单独一个分组：已实现为「资料不全」，不占前三档名额。
3. 优先修 33 家里最影响匹配的三类数据：企业性质（32 家缺）、城市（11 未知 + 8 脏值）、行业（12 家缺）。
4. 城市要做归一化：`智慧城市`、`到供需集市`、`析型数据库市`、`股上市`、`设区市` 这类不是城市。
5. 岗位抓取要区分“没抓到页面”和“抓到页面但没抽出岗位”：这次 29 家是没抓到页面，2 家是模型没抽出，2 家是规则抽取没抽出。


## 8. 岗位数据怎么处理

已经做的：

1. **落盘**：每次 `/api/lookup` 的结果写入 `ent_tools/data/lookup_cache.json`，重启后不再从 10 家变回 0 家。
2. **多查询**：`portal.py` 用「全称 / 短名 / 品牌名」分别搜 `校园招聘 / 招聘 / 人才招聘`，优先学校就业网和招聘站点。
3. **不因标签丢岗位**：页面有真实岗位但没写“校招/社招”时，保留岗位并标成 `社招信息`，不再直接清空。
4. **人工补录**：页面「资料不全」分组每家都有“补岗位”，可以贴招聘页链接或岗位文本，抽岗位后写回缓存。
5. **结果分组**：没岗位的企业不参与「优先去 / 可以看 / 建议放弃」，单独放在「资料不全」。

重跑这 33 家后，规则抽取额外补到 **3 家**：

- 国元证券：财富管理管培生
- 北京海量数据：开发工程师
- 江苏共创人造草坪：8 个管培生岗位

`lookup_cache.json` 现在是 **15 / 43 家有岗位**，其余 28 家仍缺岗位。新增的 3 家规则抽取来源是学校就业网/招聘页；腾讯和京东方用无头浏览器渲染官方招聘页后补到：

- 腾讯 `join.qq.com/post.html`：5 个岗位类别（页面显示共 1001 个岗位，当前只抽到类别，不是 1001 条明细）
- 京东方 `career.boe.com/professionals`：5 个社招岗位

`求职助理`这类导航词已从标题里过滤掉。

离线 `companies.json` 也已同步：118 家企业，15 家有岗位（共 114 条岗位），`company_module.py --validate` 通过。

> 后续对 118 家做了全量搜索，`lookup_cache.json` 已覆盖为 118 家：37 家有岗位、81 家资料不全；`companies.json` 同步为 118 家、37 家有岗位、277 条岗位。本报告的 43 家漏斗是当时的快照。
